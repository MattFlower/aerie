# Architecture

`AerieCore` owns platform-neutral settings, counter-rate rules, fixed-capacity history, notifications' threshold state, weather data/decoding, calendar arithmetic, whitelisted drive metadata decoding, formatting, and approximate lunar calculations. Its tests use synthetic input.

`AerieNative` is a small C boundary for Mach CPU/VM counters, 64-bit public interface MIB counters with an explicitly limited route fallback, libproc accounting, and read-only SMC transport. It releases Mach ports, kernel arrays, registry objects, and heap buffers. CPU accounting converts Mach absolute time to nanoseconds using the host timebase.

`AerieApp` owns AppKit status items and a reused popover, manually drawn charts and statistics, preferences, IOKit collectors, calendar integration, notifications, and weather scheduling. One utility queue serializes system sampling. Demand sources use separate utility work: one built-in OS process logger while Network is visible, and finite sequential read-only disk metadata commands at most once per minute while Storage is visible. No shell interpreter or elevated helper is installed. Core data remains independent of AppKit for a later Linux collector/UI adapter; Linux support is not implemented.

Expensive process accounting is sampled only while a visible CPU, memory, storage, or power dashboard needs process rows. Switching modules updates demand; closing clears its process cache. Pausing or system sleep cancels the sampling timer; resume clears baselines and creates one timer. System sampling uses a visible 0.5/1/2/3/5-second interval, with 100 ms tolerance. Interface names/addresses, mounted-volume, storage-device, accelerator inventory and Wi-Fi details refresh every 30 seconds; interface topology/path changes invalidate the interface inventory. Changing storage-device identities clears aggregate rate baselines. Interface counters, all supported sensor values, CPU, GPU, memory and disk activity retain the selected system cadence. Prepared sensor descriptors avoid repeated metadata lookup, string decoding, label construction and sorting. Unchanged status titles, images and accessibility values are not redrawn. Failed memory reads become explicitly unavailable/stale, clear numeric observations and rate baselines, and contribute no memory history or threshold inputs. Weather requests are ephemeral, cancellable, and refreshed every 15 minutes after opt-in. Raw readings are not written to a public log.

## Native presentation

The menu uses an original ridge mark and AppKit's native control behavior. Typography is the macOS system face with aligned numeric digits. The layout is a 416-point column: module control, scrollable statistics and history, then settings/history-window controls. Sections encode metric categories rather than decorating separate cards.

Charts use blue (#246DA2) for CPU/incoming traffic, teal (#159C94) for memory, rose (#C95471) for outgoing traffic, and gold (#D39D35) for power. Backgrounds, text, separators, and focus use adaptive macOS semantic colors. This keeps system integration while making the telemetry readable in light and dark modes. Motion is limited to requested chart updates and user-started map animation. Calendar date/navigation buttons and local event-detail actions use native controls; closing or changing the menu releases their rows, controls and event cache.

## Platform constraints

Driver registry statistics and SMC firmware keys vary across OS/hardware releases. The app never guesses missing values or performs fan writes. Normal-user libproc accounting can exclude protected processes. Calendar/notifications/login features have explicit permission controls. Wi-Fi SSID is unavailable where Location Services blocks it. A capability report and the remaining-work table keep these boundaries visible.

## Notifications

Threshold rules support individual editing, deletion and enabled state. Changing a definition starts a new sustain period. Change rules establish a baseline for connection, power source, charging, Low Power Mode, thermal state, mounted volumes, daylight saving time and time zone. The first reading, missing-data recovery, pauses and sleep gaps cannot fire a change. Cooldowns consume suppressed transitions rather than delivering an old transition later. Volume identities refresh with inventory every 30 seconds; other states use the selected system interval. No notification permission is requested automatically.

## Network accounting

The primary collector reads the public `net.link.generic` interface MIB in one batch, retaining full cumulative 64-bit byte counters. The route fallback parses each record by its common four-byte header, skips short address messages, and validates all bounds. Route byte counters can be rounded to 1 KiB and narrowed to 32 bits by macOS for ordinary applications. This fallback is labeled in the dashboard and is never described as totals since boot. A counter reset or source-width change discards the rate baseline. No shell process, private entitlement, or elevated helper is used for interface sampling. See Apple's public [route source](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/net/rtsock.c) and [interface MIB source](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/net/if_mib.c).

## Storage metadata

Each I/O source keeps its registry identity for counter baselines and associates a whole-media BSD name when available. Disk Arbitration supplies mounted-volume BSD names; the documented read-only OS command fallback reports physical-drive metadata and APFS backing relationships. Snapshot volume identifiers resolve through their base volume, and multi-store or virtual/image relationships remain explicit. Only whitelisted device/bus/media/size/status fields enter the model. Unsupported health stays distinct from a verified threshold status. No device writes or diagnostics run. These finite command processes must be included in active-view resource measurements.

CPU-complex, CPU-core and GPU clock-state telemetry uses a small dynamically resolved IOReport adapter, separately from Mach scheduler load and accelerator utilization. The private system ABI is optional: all required symbols resolve before any subscription, and channel/subscription/sample failures remain explicit. The collector owns three narrowly selected, read-only subscriptions and samples them at its existing interval, without a child process or extra timer. Cumulative state counters cross the boundary as bounded values (128 total channels, 64 states per channel). Only one previous numeric baseline is retained. Native subscriptions release on sleep, collector teardown or bounded reconnect; every sample dictionary releases after copying. OS-internal subscription/sample allocations still require physical-footprint measurement.

State distributions use channel-local counter deltas; channels and aliases can describe different power domains and are never summed into invented CPU groups or attached to an arbitrary GPU. An active-labelled fraction requires a recognized inactive bucket and known labels for every occupied state. Frequency is an active-state interval mean only when every occupied active state explicitly names a plausible Hz unit. Performance-state indices alone never imply a frequency. Counter reset, overflow, unknown occupied labels, topology/unit changes, missing channels, time reversal and long gaps withhold derived readings. Native state details show the reported distribution and these limits. Verified firmware frequency/role mapping, Intel coverage and real native UI remain open work. Apple publishes IOReport usage in its [PowerManagement source](https://github.com/apple-oss-distributions/PowerManagement/blob/main/pmset/pmset.m); private interfaces may change across releases.

Offline daylight is a pure Foundation model for one explicitly supplied local point/time zone, with no location service, request, credential or calendar access. It computes geometric solar position from published solar equations, then finds horizon and civil/nautical/astronomical crossings within the actual local civil day. A five-minute grid with refined extrema preserves brief near-polar transitions; root refinement returns absolute instants across DST, leap days, fractional offsets and the date line. Continuous above/below states remain distinct from an unavailable estimate. Solar noon is solved independently from the equation of time. The model's supported range is 1901–2099, and standard-horizon/refraction assumptions do not account for local terrain or atmospheric variability.

The native Time panel caches only one day's result for the configured point and releases it on close, pause, disable or module change. This adds no sampling timer or idle computation while off, and does not enable weather or read calendars. The default/legacy setting is absent; disabling removes the point and export removes its coordinates. Synthetic mathematical and off-window tests cover seasons, polar states, DST day lengths, date-line/fractional-zone/leap-day events, narrow crossings, bounded flat-curve work, invalid inputs and cache release. A published [NOAA mathematical reference](https://gml.noaa.gov/grad/solcalc/calcdetails.html) checks one sunrise/sunset/noon/day-length case to within one minute; this limited agreement is not a general observational accuracy guarantee. The NOAA calculator is no longer actively maintained. Real native layout and enabled-view footprint still require validation.

Individual sensor thresholds retain the four-character firmware key and its native unit, independently of display aliases and temperature display units. Unit mismatch, missing, nonfinite, failed or deferred readings supply no rule value and reset sustain state. Settings validates up to 1,024 short local aliases and the existing 50-rule limit. Full sampling remains default; in explicit on-demand mode, enabled valid rules require only their specific keys in addition to every temperature at the chosen system cadence. Required keys update on the collector's serial configuration queue. Only configured sensor inputs are copied into a transient rule dictionary; they never enter the fixed numeric history series or checkpoint format. Alias edits preserve visible keys and rule identities and do not verify hardware roles.

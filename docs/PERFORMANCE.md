# Reproducible performance protocol

## Measurement

Use a release build with matching visible features, process counts, refresh intervals, and history configuration. Record UTC timestamps, OS/toolchain, hardware privately, power/thermal state, settings, process inventory, and scenario boundaries. Include every related process and helper; do not count only resident memory or omit a daemon.

`AerieMeasure` emits JSON Lines using libproc `ri_phys_footprint`, resident bytes as a separate field, CPU percentage (one logical core = 100%), and interrupt wakeups per second. It retains every observed PID plus process-start identity, including exited or reparented descendants. PID reuse cannot inherit a previous identity or rate baseline. Related helpers launched independently must be listed explicitly. A denied/exited identity marks affected metrics incomplete rather than silently lowering totals. Physical footprint, CPU and wakeups each have a completeness flag; incomplete totals are JSON null. The first sample and newly observed helpers have no CPU/wakeup baseline and are incomplete for those metrics. Record helpers present before launch as explicit selected PIDs. Historical measurements made before these completeness fields existed must retain their caveats; do not rewrite raw evidence.

```sh
swift build --build-system native -c release --product AerieMeasure
.build/release/AerieMeasure --pids 123,456 --scenario idle --duration 60 --interval 2 > /tmp/idle.private.json
footprint -p 123 -p 456 --noCategories
top -l 31 -s 2 -pid 123 -pid 456 -stats pid,command,cpu,mem,threads,idlew,power
```

Raw output contains process names and should stay outside the repository. `footprint` may deny protected daemons; `top` can provide supplemental physical-memory evidence. Report that limitation and retain the daemon's accessible footprint/CPU evidence. `top`'s IDLEW is a different statistic from libproc interrupt wakeups; do not compare them as equivalent.

## Scenarios

1. Idle: all enabled collectors, normal menu-bar display, menus/settings closed; settle, then sample at least 60 seconds.
2. Active menu: CPU/process/history panel open, same process count and CPU display format; settle, then sample 60 seconds. Repeat for sensor-heavy and memory panels.
3. Sustained: ordinary shared-machine workload, at least 10 minutes; inspect bounded history and footprint trend without inducing CPU/GPU/storage load.
4. Settings: settings window open; measure separately from ordinary idle.
5. Maps: each implemented map layer, animation, and layer switching; include helper processes and verify release after close.

Report median, 95th percentile, and peak physical footprint, CPU, and wakeup rate. Match scenario conditions across runs. Background workload and system compression can affect measurements. A favorable early sample does not satisfy feature-complete acceptance.

## Network scope and counter continuity

Aggregate interface rates require a valid finite baseline for every selected active interface. A missing/reset member makes that direction unavailable instead of publishing a partial sum into charts, numeric history or threshold rules. Individual interface rows and valid zero rates remain available; an unselected or inactive interface does not invalidate the selected scope. Native collection failure withholds aggregate rates.

Native interface collection remains complete at the chosen system interval. Network Settings can select which active interfaces feed aggregate bandwidth, history and download/upload rules; unselected interfaces are still sampled and displayed. The default sums all active interfaces, which can duplicate traffic through virtual tunnels. Choosing one side avoids that aggregation duplication without reducing collection. Changing scope clears only download/upload history and their pending aggregates, preserving CPU, temperature and other series.

Observed session totals begin at zero at each interface's first reading; prelaunch cumulative traffic is not credited. Counter rollback/wrap or a 32/64-bit source change rebases that interface at zero and shows a new baseline time. Disappearance or a failed complete interface read clears its observation session. These are per-interface observed sessions, not a permanent whole-machine usage ledger. Source failures stay unavailable. Synthetic tests cover large 64-bit cumulative values, source continuity, missing interfaces, scope changes and isolated history clearing. Full-interface native regressions remain mandatory for every build.

## Process grouping and sorting

Process combining defaults off. When enabled, only visible CPU/memory/storage/power or TCP/UDP process views read executable paths, using the existing system tick. Each bounded 4 KiB read rechecks the process's native start identity; a denied, reused, malformed or oversized identity stays separate. Group identity is the outer application-bundle path when present, otherwise the exact executable path. Display names alone never merge processes. The reader has no timer, helper, persisted path cache, file scan or network work. It copies at most8192 current identities; paths remain volatile in active process rows and are excluded from settings, history, exports and diagnostics.

Groups are formed before ranking and applying the displayed process-count limit. CPU/I/O/traffic/wakeup rates are sums only when every member has a valid baseline; valid zero and unavailable remain distinct. Summed physical footprints can include shared-accounting overlap and are labeled as summed process accounting. Per-panel sort choices use already collected metrics and leave the displayed value's unit/CPU normalization unchanged. TCP/UDP remains independent of aggregate interface selection. Leaving process views, closing the panel, pause and sleep discard active rows and grouping metadata through the existing demand owners. Measure enabled grouping source cost and real post-close release separately; default-off or synthetic checks do not establish that budget.

## Sensor sampling configuration

Full hardware-sensor sampling remains the default for new and legacy settings. Every supported source is read at the chosen system interval; failed readings stay in the inventory with unavailable values. An explicit General Settings option can defer fans, power, voltage and current until the Sensors panel needs them. It always samples every temperature at the original interval because maximum-temperature history and threshold rules require them. Opening Sensors restores all families at that same cadence; closing it removes deferred live values instead of reusing stale values or treating them as zero. There is no automatic battery/low-power sampling reduction.

Disclose this option in every measurement. A run using on-demand sensor families is a different configuration from full sampling and cannot prove full-sampling feature/performance acceptance. The development-only `--sensor-sampling-demand` launch argument applies the option for that process without saving it; `--background --self-check` reports inventory, live/deferred source counts, temperature coverage, network counter width and interval. It does not exercise a real open panel. Synthetic regressions verify identical temperature history/rule inputs, full inventory retention, visible-panel restoration and missing-value semantics. Real panel transitions still need UI validation.

## CI cost boundary

As verified on 2026-10-11, [GitHub documentation](https://docs.github.com/en/billing/concepts/product-billing/github-actions) makes standard GitHub-hosted runners free for public repositories. Larger runners are billed. CI uses `macos-15`, read-only repository permissions, no Actions artifact/cache uploads, a timeout, and concurrency cancellation. It skips when the repository is private. Account billing APIs may require an additional scope; no credentials or budgets are changed to obtain it.

Map HTTP transfers enforce their response byte budget while receiving chunks, including unknown-length responses. A rejected body does not enter the raster cache; suspension cancels in-flight and paced work. Synthetic tests cover exact-limit responses, oversize headers, chunk overflow, cancellation and subsequent recovery. Real active/post-close peaks remain pending.

History export is an explicit local save-panel action and contains only the selected retained range. Minute/hour summaries retain per-metric observation counts; missing readings are not counted. Averages are sample means, not time-weighted means. Chart coordinates use elapsed time, and breaks occur after missing readings or gaps longer than three expected intervals. Backward/duplicate wall-clock readings reset retained history and aggregation baselines. Persistence is off by default for new and legacy settings.

Opt-in persistence checkpoints the same retained numeric series and validated interface-scope identifiers in a local Application Support file, without process/sensor/volume names, paths, event details or weather data. At most 2 MB is read or written, with bounded receipt and validation of schema, keys, counts, monotonic/future dates, source scope and retention capacities. Pending minute/hour sums and counts survive restart without replaying old samples into aggregates. Elapsed retention is trimmed, and changed network scope removes only download/upload history. A utility queue owns serialization and file I/O; at most one checkpoint job exists even if file work is slow. Saves occur once per minute and on normal exit, using a same-directory 0600 temporary file and atomic rename; old/new files can briefly total 4 MB. Invalid or oversized data never replaces a valid archive. Load/disable generations discard late results; disabling through Settings deletes only the archive, with errors reported as unavailable. File-system service stalls can still delay shutdown while ordered work finishes. Background checkpoint copies and serialization have memory/I/O cost and require separate enabled-history measurement. No collector cadence changes. Synthetic fixtures cover restart counts, expiration, schema/size/time rejection, isolated scope invalidation, private permissions, cancellation, ordered deletion and slow-worker queue bounds. `--history-archive-path <absolute-local-file>` explicitly enables process-only development persistence at a caller-chosen path without saving that preference; it never supplies a location or permission grant.

Combined menus retain an ordered choice of 1–6 modules, independently of separate item visibility, and all collectors retain their original cadence. Two-line native images fit a 20-point height and a bounded 360-point width; long content truncates visually while accessibility and tooltips retain bounded full values. Automatic colors use macOS template/semantic behavior; explicit RGB applies to text, graphs and stacked values. Images rebuild only when their displayed values change. Synthetic native raster tests verify dimensions and drawing, while real light/dark, contrast, menu-bar layout and accessibility interaction still need an unlocked Mac.

Native history controls zoom by 2/4/8 and pan within each retained resolution using timestamps. Missing values, long gaps and observation counts survive filtering. The latest position follows incoming data; reset restores the full retained range. Export captures precisely the displayed filtered points before the save panel opens. These controls introduce no sampling timer or unbounded storage. Synthetic model and off-window control tests verify elapsed-time selection and missing/gap semantics; real pointer/keyboard/screen-reader/export interaction remains open.

Global shortcuts are off in new/legacy settings. Only explicit valid configured combinations register through the OS hot-key API, with Command or Control required and no general keyboard-event monitor. At most one per module plus Settings is registered. Character keys resolve against the active keyboard layout; layout changes release old registrations and resolve new ones. IDs are not reused during an app lifetime, preventing late events from dispatching a changed binding. Clearing configuration or quitting releases every hot key, handler and layout observer. OS conflicts, reserved keys, secure input or unavailable layout data can prevent availability and remain visible failures. Synthetic injected-driver tests exercise disabled defaults, conflict handling, layout reconfiguration, release and stale IDs without registering actual keys or requesting any keyboard permission. Real shortcut registration/delivery/layout/secure-input validation remains open.

Calendar Today remains relative to the current local day across long closed intervals and day/DST rollover; explicit date/month selections stay pinned until Today or panel close. This does not create an extra collector or event polling cadence.

Process network summaries own one built-in OS logger and temporary terminal only while the Network panel is visible. Closing/changing the panel, pausing or sleeping terminates it and clears the source/rate state; interval changes restart it. All logger descendants belong in Aerie active-view and post-close cohorts. The OS logger uses integer-second intervals: `ceil(max(1, systemInterval))`, disclosed in the panel; a 0.5-second system setting therefore reads process traffic at one second. TCP/UDP process totals include loopback and all OS-reported interfaces independently of aggregate interface selection. Protected identities are counted as unavailable, first/reset/sleep/PID-reuse rates are blank, and stale streams do not retain live rates. A fresh native kernel adapter remains a potential future replacement for the OS logger. This implementation needs real panel/active helper peak and repeated reclamation checks.

`--background --process-network-self-check` exercises twelve source ticks of logical network demand, clears demand, waits three seconds for helper release, prints only coverage/status and exits. `--background --network-demand-cycles` starts demand at 3, 68 and 133 seconds for 45 seconds each, then clears it. These explicit developer commands do not open a real menu, render its rows, change saved settings or substitute for UI acceptance; they permit repeatable source/helper lifecycle telemetry on a locked development host.

Measurement retains exited helper identities in every later record. Only a verified kernel `ESRCH` or a different known process-start identity confirms exit. A confirmed exited process has zero current footprint; CPU/wakeup rates for the transition interval remain unavailable, followed by zero for wholly post-exit intervals. Missing/protected/unidentified processes remain incomplete. Output flushes each JSON record so lifecycle transitions can be observed contemporaneously.

Storage I/O sources remain sampled at the system interval. Registry whole-media association refreshes with the existing 30-second inventory. Disk Arbitration supplies mounted volume BSD names; APFS multi-store/snapshot relationships and reported SMART status use documented read-only `diskutil list/info/apfs list -plist` queries at most once per 60 seconds while the Storage panel is visible. Commands run sequentially, have 2 MB output and 5/6-second termination/kill bounds, inherit a minimal environment and are cancelled/released on hiding, pause or sleep. Include every transient command process in active-view measurements. No diagnostic scan, repair, device write, elevated installation or new persistent permission is used. Unknown/unassociated/unsupported/failing statuses stay distinct; SMART Verified is a threshold report and does not establish remaining lifetime or a complete diagnostic pass. Drive temperature/endurance are not inferred.

`--background --storage-self-check` exercises logical read-only Storage demand, prints only coverage/status counts, clears demand and waits 7 seconds for bounded query cleanup. It does not render a real panel or substitute for active-view measurement.

Calendar controls use the configured local calendar, first weekday and week-number setting. Adjacent-month dates are selectable, month navigation clamps short/leap-month days, and selected event ranges follow calendar day boundaries through DST. Events are read only after existing full calendar access, only for the Time panel. A serial utility queue exclusively owns each EventKit query store; enumeration replaces a main-thread fetch/sort of the entire event array. Each selected-day or configured upcoming 1–31-day range stops after 2,000 scanned events and retains only the earliest 20 of that scanned subset, with bounded copied text. Scan truncation is disclosed because framework enumeration order is unspecified. EventKit's internal query allocations are outside this retained-result bound and still need real dense-calendar footprint validation. Stores reset/release on the worker queue after each query. Cancellation, close, change, pause, sleep and access revocation discard pending/late results and clear event details and native controls. Permission-request stores release after both grant and denial; permission is requested only through the explicit Settings action. No event contents enter history or diagnostics. Ordinary open-panel refresh is once per minute, with local calendar-change invalidation; this does not alter system collector cadence. Synthetic dense-calendar, denied/revoked-access, rapid-reopen, cancellation, late-result and store-release tests exercise injected sources without requesting access. Real rendering, keyboard/screen-reader interaction and an explicitly approved permission path remain pending.

Demand-only drive metadata clears from the reader, collector cache, application snapshot and dashboard when Storage closes or changes, and on pause/sleep. Each incoming snapshot rechecks current UI demand so late queued results cannot restore it. Synthetic owner/close/pause tests accompany query generation tests. Helper instrumentation also records kernel-reported lifetime maximum physical footprint when available. This catches earlier spikes before a successful reading, but a missing final reading still leaves the end of a command unresolved. Separate process lifetime maxima are not simultaneous aggregate peaks and must not be added and labeled as such.

`--background --storage-demand-cycles --storage-command-measurements` is explicit development instrumentation for three logical 12-second demand windows starting at 3, 38 and 73 seconds, without rendering a panel or saving settings. It registers every direct finite command at launch and confirmed reap, with a separate BSD birth identity for guarded timeout cleanup even when resource accounting is denied. Resource snapshots of the app and that command are attempted immediately and every 25 ms while it runs. Missing/denied or identity-mismatched values remain unavailable; current helper footprint becomes zero only after the owned child is reaped. CPU/wakeup counters are cumulative and cannot supply a rate for a missing first or exit-transition interval. Sampling and JSON output add measurement overhead. A sampled maximum is a lower bound on instantaneous peak and can miss very short-lived allocations; lifecycle registration alone does not prove every transient resource reading or unobserved descendant is captured. Use independent all-process sampling as well, retain coverage/errors privately, and measure the post-close tail. This instrumentation is off in normal use and public CI. Read-only storage commands retain 2 MB output limits and 5/6-second terminate/kill deadlines; synthetic overflow and SIGTERM-resistant-child tests verify reaping.

Only implemented forecast providers are accepted in settings and request builders. An unsupported provider selection fails validation instead of sending its coordinates to a different service. Open-Meteo and NWS each use an ephemeral provider-specific session, with no cookies or URL cache, bounded 2 MB bodies during receipt (including unknown-length/decompressed chunks), 20-second request/30-second resource timeouts, and exact HTTPS host/path validation for redirects. Cancellation and completion resume each request once; the session closes after every forecast attempt. NWS uses at most eight sequential requests per 15-minute forecast refresh. Weather remains off without manual provider/location consent. Native forecast/alert detail windows retain bounded report text only while open; they initiate no extra HTTP work.

Process completeness flags cover selected and observed identities. Periodic descendant discovery can miss a command whose entire lifetime falls between external samples. Active Storage peak validation therefore also needs explicit spawn/exit registration or lifecycle tracing with timely resource samples; a closed-panel run or a poll that sees no child cannot prove its active helper budget. Keep that limitation explicit until the finite-command lifecycle measurement exists.

Clock-state subscriptions add native collection at the unchanged system cadence. Include their CF allocations and the bounded per-channel/state baseline in full-default measurements, including enabled history and transient Storage helpers. No privileged reader, child process, polling timer or hidden slower interval is introduced. Source failures retry no more than once per minute; sleep closes handles and wake establishes a new baseline immediately. Synthetic injected-source tests verify failure/reconnect cadence, release, invalid status metadata and fresh baselines. These tests do not open actual subscriptions. Native availability and physical-footprint checks remain separate from real CPU/GPU panel and detail-window acceptance.

Event-calendar selection is local and retains only validated opaque calendar identifiers in saved settings. All, an explicit subset and None are distinct; None creates no EventKit query store. Missing selected calendars are counted and never cause fallback to all calendars. The native selector reads names only on explicit opening with existing permission, without a grant request. A serial utility worker owns and releases its inventory store, returning at most 128 copied names/identifiers; the framework's internal calendar-list allocation is outside this copied-result bound. Cancellation/close/hiding/revocation discard late results and clear native name controls. Reopening obtains fresh names; saved missing identifiers remain choices, while exported settings remove all event-calendar identifiers. All includes calendars beyond the bounded picker list; manually selected calendars are limited to 128 with an explicit limit message. Real chooser, permission/revocation and active/released footprint checks remain open.

Offline daylight stays off without an explicit manual point. It has no HTTP work, location request, helper or timer; its bounded crossing work runs once for a cached point/local day while the Time panel needs it. Cache release on close/pause/module change/disable accompanies synthetic regressions. Default sustained measurements do not establish the enabled Time-panel allocation/CPU cost, which needs its own real active/post-close scenario. Solar estimates and manual coordinates never enter numeric history checkpoints or diagnostics.

Sensor aliases do not change the inventory or sampling interval. Individual rules add at most 50 configured transient inputs and do not expand any history ring or archive. With no individual rules, no sensor-value dictionary is constructed. Explicit on-demand mode continues reading all temperatures and each enabled valid rule's required key while the panel is closed; that configuration must be disclosed in comparisons. Native rule/alias controls have synthetic off-window action coverage, while real Settings, notification delivery, enabled-rule cost and post-close footprint acceptance remain pending.

External-address lookup defaults off and creates no reader/session/task in that state. Opting in uses one bounded512-byte ephemeral HTTPS reply every five minutes through the system tick, without slowing any collector or adding a timer/helper. Path changes, failures, disable, pause and sleep invalidate or release live state and cancel old work without a retry burst. Include opted-in HTTP/session costs in separate comparable enabled-source measurements; default-off captures do not cover them. Synthetic transport/cadence/lifecycle tests perform no live address query. Real consent/control/delivery and active/released memory checks remain open.

CI uses standard public macOS14/15 Apple Silicon and macOS15 Intel jobs, with synthetic inputs only and no sensor/permission/network integration requests. The matrix checks compilation and native off-window framework actions on the minimum OS and both CPU architectures. It does not measure the user's device or establish sensor, real UI or physical hardware coverage. Jobs remain skipped for private repositories; no artifact uploads, cache uploads, paid labels or account-spending changes. ## Optional phase diagnostics

Launch the packaged executable with `--background --sampling-profile` to inspect sampling work without a separate timer or skipped source. This mode emits bounded JSON timing totals every 60 existing sample deliveries, separately for the serial collector and presentation thread. It measures monotonic wall time and current-thread CPU time for native clock receipt, decoding, residency derivation, full sensors, interfaces, other collectors and presentation work. Missing/reset/overflow CPU clocks retain explicit valid sample counts; observed sums are not complete totals when coverage is missing. It contains phase identifiers and timing/counts, never readings, process names, interface names or locations.

Timing reads and report serialization add overhead. Use this mode to locate work, then compare release measurements with diagnostics off. A wall-time sample includes blocked time and cannot substitute for CPU time. Short stack profiles can miss rare work, and a change that adds telemetry must be distinguished from a regression under an unchanged feature configuration. Keep raw profiles and measurement settings private.

Clock sampling merges available CPU-complex, CPU-core and GPU channel dictionaries into one read-only subscription when the optional system merge interface is available. Each channel keeps its original group through its driver/channel identity; the subscribed catalog must exactly cover the requested identities. Ambiguous identities, unavailable merge support, merge failure or incomplete subscription coverage retain the separate-subscription fallback. Missing/new/duplicated sample identities produce explicit unavailable status and the existing bounded reconnect path. Every channel and state counter is still read at the unchanged system interval. `--self-check` reports the active subscription count alongside group and residency coverage without exposing channel identities. This reduces repeated native sample receipts, without slowing sampling or discarding sources. Synthetic catalog/collision/bound/diagnostic tests supplement native inventory and performance validation.

Power-source descriptions use the existing read-only IOPS snapshot at every system tick. Up to64 battery/UPS descriptions retain bounded copied text and documented per-source capacity, presence, input, charging, time and electrical values. Truncated/unreadable inventory and missing keys remain explicit. Boolean capacities, non-finite values, negative/sentinel time and unsafe integer conversion are rejected; zero charge/current remain valid. The battery summary and history use exactly one explicitly present internal battery only when the complete inventory makes that choice unambiguous. UPS capacity never overwrites it, and multiple sources with unknown capacity units never produce an invented combined percentage. Registry battery health/cycles/electrical enrichment requires that same unique internal battery. This adds no source timer, helper, control write, permission request or cross-source aggregation. Source names/transport and descriptions do not enter numeric history or diagnostic output. The framework's internal snapshot allocation is outside the retained64-source bound. Synthetic mixed-source, ordering, unknown, absent, overflow, electrical-unit and native-row tests do not establish real UPS/hot-plug coverage or unlocked Power-panel acceptance.

Dashboard accessibility objects are reused as live values change, with labels and frames updated in place. Row-kind changes replace only the affected object; removed/closed rows clear parent links and release the retained objects and selected/chart-view point copies. Charts expose an accessible press action to inspect the middle retained sample; native pointer clicks choose their horizontal sample, and accessible labels include the selected date/value. These changes preserve every collector, row and full retained history ring. Explicit manual launches and reopening a running menu-only app through macOS open Settings. Background/self-check commands and OS login/service launch markers retain quiet startup; actual Launch at Login registration is outside these synthetic launch-metadata tests. Real panel/helper/graphics peaks and repeated post-close reclamation still require process-level measurement; off-window lifecycle tests alone do not establish the budget.

The menu dashboard uses an opaque native AppKit utility panel anchored and clamped to its menu item's screen. It retains the same dashboard controller, every metric/detail/history control and the same sampling demands. The panel/window/content attachment releases on close; Escape and native close controls dismiss it, app hide closes it, and changing focus to another application schedules a guarded close without affecting a newly reopened panel. Ordinary native window composition avoids a full translucent popover backdrop. This is a presentation implementation choice, not evidence of a passing footprint budget: real active/closed paired measurements and repeated cycles remain necessary under shared-host contention. Chart accessibility explicitly exposes enabled actions, and menu style/order selectors include their module names.


Long dashboard inventories retain every row in stable accessibility groups of at most64 leaves, rather than a single flat list. The accessible document root reports its scroll viewport; visible groups follow scrolling while the complete hierarchy remains available. Short dashboards retain their direct row structure. Synthetic native tests cover full600-row traversal, live identity/value updates, viewport frames, scrolling, pruning and close cleanup. Actual screen-reader/client traversal still needs real-window validation. Closed Settings and detail windows also detach their native content. The standard Window menu offers Close and Close All Aerie Windows, with Command-W and Option-Command-W respectively. Closing managed windows does not change the sampling configuration.

`--window-lifecycle-measurements` enables private development diagnostics. It adds no timer and is off by default. Existing delivered system ticks and native window/application transitions emit subsecond epoch/monotonic timestamps, opaque stable window IDs, fixed roles, visibility/occlusion/minimization/content-attachment flags, and the app's BSD birth identity, kernel resource identity, physical footprint, CPU time, interrupt wakeups and native lifetime peak. Titles, row values, coordinates, settings, locations and other applications are never recorded. Weak window references cannot retain a closed window. At most256 windows and128 events per second are tracked; omitted windows and dropped events are explicit. Unknown process-local native windows remain auxiliary presentations, rather than being excluded from an all-closed claim. Status-item windows are identified from their own buttons and excluded from presentation counts. A minimized window remains a retained presentation.

The diagnostics allocate/encode output and read resources only while enabled, so their overhead must be disclosed and the normal release budget must also be measured with them off. They observe AppKit's process-local public windows/notifications; they do not guarantee coverage of every framework-private or WindowServer surface. A will-close event can precede ordering out and detachment: require subsequent existing ticks that report all presentation windows closed before calling a tail idle. Paused/sleeping collection may stop tick records. No extra diagnostic sampling is introduced to fill that gap. Exact helper launch/resource/reap records and external process sampling remain necessary; app lifecycle records alone do not measure helpers.

For paired GUI checks, use one final release build, identical sources/history/settings and normal cadence: record at least30 seconds with all presentation windows closed, open one panel for at least10 seconds, close all windows, then record at least25 settled seconds. Repeat three times and retain transition timestamps and every process/error/exit identity. Preserve real active peaks and unobserved transient-helper limitations. Compare closed tails separately from Settings-open or minimized states; short tails are diagnostic evidence, not sustained acceptance. Keep real-machine captures and screenshots outside the repository and public CI.

## Offline time presentation and rule episodes

Compact, large and analog world clocks draw native text/paths in the existing dashboard. At most 20 configured clocks share the current sample delivery; no clock timer, background cache, image asset or auxiliary window is added. Civil-date labels and UTC offsets distinguish repeated daylight-saving hours. Calendar systems and upcoming ranges use Foundation calendar arithmetic; ISO week labels follow each row's Thursday, independently of its first displayed weekday. Existing event bounds and permission requirements remain unchanged. Synthetic bitmap drawing and off-window configuration tests do not establish real rendering or the enabled active-window budget.

Threshold recovery bands apply only after a valid reading enters a condition. Missing values, time discontinuities, pause and sleep clear active episodes and sustain time; existing cooldown persists. Once-per-episode rules rearm only after recovery/reset, while legacy rules still repeat after cooldown. Range upper bounds and band widths are validated, and storage I/O conditions use already-collected rates. No scheduler, source or history series is added. Enabled-rule/source cost and actual notification delivery still need final acceptance.

Firmware decoding has exact byte-width checks for supported numeric formats and rejects nonfinite, malformed or unknown payloads. The pure decoder performs no hardware read and establishes no hardware role, frequency/light unit or additional source support. Supported sensor families and sampling cadence remain unchanged. Discovery validates declared numeric metadata without a duplicate startup value read; a supported source stays in the inventory when its first live sample fails. Integer state keys, unverified light/frequency formats and unknown encodings acquire no inferred unit. Friendly sensor labels derived from common key conventions explicitly say “unverified role”; they do not establish device-specific CPU/GPU, ambient or other physical roles. User aliases remain local labels. Verify actual inventory/readability and source cost on the final commit.

Packaging removes only FinderInfo from the generated app directory before ad-hoc signing, if present. This handles Finder metadata on build outputs; other extended attributes and installed applications are preserved. Strict bundle verification is performed immediately after signing and remains required on the final output. Optional `AERIE_BUILD_SCRATCH` and `AERIE_APP_OUTPUT` paths permit local build databases and bundles on filesystems suitable for compilation/signing; defaults remain `.build` and `dist/Aerie.app`.

Configuration transfer reads at most 1,000,001 bytes and rejects files over 1,000,000 bytes before JSON decoding. Exports apply the same bound. Profile review/staging has no sampler, helper, timer, network or OS-permission side effects. Imports and defaults clear external-source/location/event selections and preserve the existing numeric-history preference; staging does not call the application apply callback or touch its defaults/archive. A separate Apply changes collection configuration at the displayed interval and uses the existing scope/history reset behavior. Native confirmation, chooser, discard/apply and profile-window allocation need real UI validation; synthetic tests run off-window with an injected review decision and no saved preferences.

Change-rule settings expose one cooldown per kind. Applying a staged profile preserves existing rule IDs, order, enabled state and timing; newly enabled kinds append using their own field. Clock names use quoted JSON strings in the editor, retaining delimiters, whitespace and escaped line breaks. Plain edited names remain supported, with the rightmost pipe separating the IANA zone. Model and form validation share the 20-clock/64-character bounds, additionally limiting each name to 4096 UTF-8 bytes and each zone to128 bytes. These paths run only during settings construction/validation and add no source sampling, timers or helpers. Synthetic transfer tests are separate from real native UI/performance acceptance.

Explicit `--background` and `--self-check` development launches also stay quiet on later bundle reopen requests. This launch option changes only reopen presentation, never sampling, retained history, helper coverage or available dashboard content. Disclose it in native measurements.
